## QA server recipe

1. Snapshot the dev web image: `docker commit multi_magic-web-1 mm-qa:6de97a32-base`.
2. Detached worktree of multi_magic at prod's commit (6de97a32).
3. Run it on the dev compose network, port 127.0.0.1:3060, with its OWN database (`POSTGRES_DB=mm_qa_rc16` gives mm_qa_rc16_development). A guard prints the database name and refuses anything that does not start with `mm_qa_`. Secrets stay in a chmod 600 env file and are never printed.
4. `db:create db:migrate`, then seed only invented data (a demo user, contacts, SafeZone items, and for B: two users, a conversation, an event, notifications with paths).
5. The app reaches it through `adb reverse tcp:3060 tcp:3060`. For the release APK: `EXPO_PUBLIC_API_URL=http://localhost:3060`, cleartext allowed in the generated android/ only (never committed).
6. The emailed SafeZone code is replaced through a guarded rails runner in the QA database (a known BCrypt digest), since the QA server sends no real mail.
7. Teardown after the QA: stop the container, drop mm_qa_rc16_development through the guard, `docker rmi mm-qa:6de97a32-base`, remove the env file.
