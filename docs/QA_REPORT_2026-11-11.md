## 2 · Bugs found and fixed on the way

1. **The phone never showed a web-chosen colour.** The web stores keys
   (`"green"`); the phone accepted only hex and fell back to an id colour.
   `colors.ts` `eventColor()`. (`7f82cb7`)
2. **A refused share said "That did not work" instead of why.** The server
   sends `{ message: [ … ] }` (an array); `apiErrorMessage` read a string
   only. The phone half of the owner's 2026-11-10 share-dialog bug.
   (`d483b63`, red first)
3. **The wheel's first a11y shape hid its own rows on iOS** (a named
   container groups its controls). Caught by `a11y.test.tsx` before any
   device; rows now sit under an unnamed parent with the adjustable band as
   a sibling.
4. **`Date.now()` in render** for the Undo timeout — flagged by the React
   Compiler purity lint; expiry moved to the effect.

## 2b · Desk accessibility audit (after device pass 1)

Read from the source of every new screen, then fixed test-first
(`calendarA11y.test.tsx`, red before each fix):

- the KIND chips said "checkbox" for a single choice → `radio`; reminders
  stay `checkbox` (any of five);
- the Undo was silent on iOS (`accessibilityLiveRegion` is Android-only) →
  `announceForAccessibility`; and 8 s is too short to hear, find and reach a
  button with a screen reader → 30 s when one is on (WCAG 2.2.1);
- a neighbouring month's day drew `muted` at 60% opacity, about 2.6:1 on the
  light ground, for a tappable cell → the muted tone's own ~4.9:1;
- RTL: `‹` still means the previous month, and its glyph points to the
  line's start (right) in RTL — now pinned by a test.

Checked and fine: every control has a translated name (`a11y.test`), pills
carry `expanded`, Save carries `busy`/`disabled`, day cells say the whole
date and their event count, headings carry `header`, touch targets reach 48
dp with `hitSlop`. There is no Arabic in the app (en/fr only); RTL is
tested as FORCED RTL, and adding a language is the owner's decision.

Shot 10's interleaved composer text (supervisor's question): the probe's
`tapOn composer-input` tapped the field's CENTRE, and Android puts the
cursor where a finger lands; the draft is set once and never re-set while
typing (`useDraft`, `Composer.tsx`). Not a calendar bug. The improvement
"first focus after a pre-fill puts the cursor at the end" is BUILT as its own
commit (supervisor asked, 2026-11-11): `Composer.tsx`, released as soon as it
lands so a later tap goes where the finger is; 4 tests, two plants red. To
confirm on a device in slot 2 (tap mid-field on a pre-filled question). "Tomorrow, November 11" in shot 4 was right:
that event was created 2026-11-10 09:06 UTC for 2026-11-11 10:00 Paris.

## 10 · For the owner

- **Duration when the start moves.** Like the web, moving the start only
  moves an end that would fall behind it (3:00→3:05 kept a 4:00 end: 55
  min). Google and Apple keep the duration instead. Your call; one line in
  `draft.ts` `withStartTime`.
- **Pickers are JS.** Native quality was the bar (supervisor); the inside of
  `pickers/` can become `@react-native-community/datetimepicker` at the next
  native build without touching a screen.
- **No trash screen**, as on the web; Undo covers the delete a second ago.
- **Deploy `calendar-dst`?** It changes what the web and the phone show
  for repeating timed events after a DST change (to the right time).
- **Add an RTL language?** Only then can RTL be measured on a device.
